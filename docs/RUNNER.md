# Раннер тестов

В проекте используется `codelab/csharp-runner:1.0` образ для выполнения пользовательского кода с тестами.

> ⚠️ Исходный код Runner'а в этом репозитории отсутствует.  
> Данный документ описывает его поведение и способ интеграции.

## Как это работает

Процесс выполнения:

1. Передаётся путь к директории с кодом
2. Runner находит все `.cs` файлы
3. Делит их на:
   - Файлы решения
   - Файлы тестов (по наличию "Test" в имени)
4. Выполняется компиляция через Roslyn:
   - Все файлы собираются в одну DLL
   - Тесты предварительно переписываются (перехват `Console` вывода)
   - Подключаются .NET и xUnit зависимости
5. Если есть ошибки компиляции:
   - Тесты не запускаются
   - Возвращается статус `error`
6. Если компиляция успешна:
   - Сборка загружается в память
   - Запускаются тесты через xUnit
7. Результат сериализуется в JSON и выводится в `stdout`

---

## Входные данные

Runner ожидает директорию следующего вида:

```text
/temp
  ├── Solution.cs
  ├── SolutionTests.cs
```

- Все файлы должны быть `.cs`
- Файлы, содержащие `"Test"` в имени, считаются тестами
- Обязательно наличие:
  - минимум одного файла решения
  - минимум одного файла тестов

## Формат результата

### Успех

```json
{
  "version": 1,
  "status": "pass",
  "tests": [
    {
      "name": "test name",
      "status": "pass"
    }
  ]
}
```

### Падение теста

```json
{
  "version": 1,
  "status": "fail",
  "tests": [
    {
      "name": "test name",
      "status": "fail",
      "message": "Expected X but got Y"
    }
  ]
}
```

### Ошибка компиляции

```json
{
  "version": 1,
  "status": "error",
  "message": "Compilation error"
}
```

## Особенности

- Поддержка `Console.WriteLine` (перехватывается)
- Ограничение вывода (~500 символов)
- Стабильный вывод (InvariantCulture)
- Результаты всегда в JSON
